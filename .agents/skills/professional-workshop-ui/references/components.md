# Components

## Buttons

### Primary
Use for the dominant local action.

Examples: Apply, Generate, Save, Confirm.

Prefer one primary action per local context.

### Secondary
Use for supporting actions.

Examples: Recalculate, Preview, Import, Duplicate.

### Quiet
Use for tertiary actions.

Examples: Advanced, Reset, More, toolbar actions.

Avoid multiple strong primary buttons side by side.

## Numeric fields

Preferred row:

```text
Feed       [ 3200 ] mm/min    Modified
```

Guidelines:

- fixed/consistent field widths
- units in a dedicated column
- keyboard-editable
- sensible stepping where relevant
- no hidden unit ambiguity

## Section headers

Use small, quiet hierarchy with a subtle divider and optional chevron/action.

## Disclosure rows

Preferred for advanced information:

```text
▸ Advanced parameters
▸ Source and provenance
▸ Machine compatibility
```

Expanded content should not visually overpower the main section.

## Status labels

Prefer lightweight text/icons:

```text
✓ Validated
● Modified
⚠ Out of date
```

Avoid badge proliferation.

## Toolbars

Use:

- compact height
- small consistent icons
- grouped related actions
- separators only where meaningful
- tooltips

## Tabs

Tabs should remain compact.

Use accent only for the active tab.

Avoid pill-style mobile tabs unless strongly justified.

## Tables/lists

Use:

- restrained row height
- subtle hover
- clear selection
- aligned numeric columns
- optional compact icons
- minimal zebra striping unless it genuinely improves scanning

## Empty states

Keep concise.

Good:

```text
No tools available on this machine.
[ Add tool ]
```

Avoid marketing-style illustrations in expert desktop workflows unless specifically needed.

## Modals

Use sparingly.

Modal content should be focused and short.

For long configuration flows, prefer dedicated settings views or inspectors.
